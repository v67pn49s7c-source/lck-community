## 2026-08-11 — 홈 출시 전 참여 전환 보강

### 구현

- `index.html`: 팀 메뉴 아래 본문 첫 카드로 `home-feature-card`를 추가하고, 기존
  `LCK 팬 커뮤니티` 제목은 전체 게시판 바로 위에 유지했다.
- `assets/app.js`: 가장 가까운 경기일의 1~2경기 중 팬 참여가 많은 경기, 동률이면
  늦은 경기를 핵심 경기로 자동 선택한다. 최근 맞대결이 있으면 재대결 간격·직전 승자·
  스코어를 자동으로 문구에 넣고, 없으면 중립적인 맞대결 문구를 쓴다. 특정 팀 하드코딩은 없다.
- 관리자의 `홈 문구` 탭에서 현재 핵심 경기의 관전 제목·보조 설명을 수정할 수 있다.
  설정은 `home_feature_copy`에 경기 ID와 함께 저장하며, 핵심 경기가 바뀌면 예전 문구를
  재사용하지 않고 자동 생성 문구로 돌아간다. 기존 `site_settings`를 써서 SQL 변경은 없다.
- 상단 경기 바는 10명 미만에서 비율·그래프 대신 `N명 참여` 또는 `예측 대기`를 표시하고,
  `예측하기`를 고대비 버튼으로 바꿨다. 960px 이하에서는 하루 두 경기를 한 줄에 억지로
  넣지 않고 두 행으로 쌓으며 버튼을 `예측`으로 줄인다. 시간의 `:first-letter` 강조는 제거했다.
- 홈 게시판은 반응 없는 자동 경기방으로 다섯 칸을 보충하지 않고 의미 있는 글만 최대 5개,
  0 추천·0 댓글은 숫자 자체를 숨긴다. 홈 보조 투표도 10명 미만이면 비율을 숨긴다.
- 홈 `전체 게시판`은 **커뮤니티(전체) 글만** 보여 준다. 팀 글(`posts.team`)과 자동
  `[경기 토론]` 방(`match_id` 또는 제목 접두어)은 추천·댓글이 있어도 제외한다.
  팀 글이 홈에 뜨면 팀 게시판 비공개 정책이 홈에서 새기 때문이다.
- 팀 게시판 글은 **그 팀 팬만 열 수 있다** (`canReadPost`, `assets/board.js`).
  목록의 제목까지는 누구나 보이지만 `post.html` 진입 시 막히며, 본문·댓글을 그리기 전에
  차단하므로 meta 설명으로도 새지 않고 `noIndex()` 처리된다. 공지와 관리자는 예외다.
  **서버도 함께 막는다 (schema26).** `posts.body` 컬럼 읽기 권한을 anon·authenticated 에서
  회수하고, 본문은 `get_post_body(p_id)` 창구로만 나간다. 댓글·글투표도 `can_read_post()`
  기준으로 좁혔다. 그래서 브라우저 코드를 건너뛰고 PostgREST 를 직접 불러도 본문이 안 나온다.
  · **비회원은 팀 게시판 글을 읽을 수 없다** — 서버가 비회원의 응원팀을 확인할 방법이 없다
    (응원팀이 localStorage 에만 있다). `canReadPost` 도 같은 규칙이라 화면과 서버가 일치한다.
  · 목록 요청은 `select("*")` 가 아니라 컬럼을 나열한다. **여기를 `*` 로 되돌리면 목록
    요청 전체가 권한 오류로 죽어 사이트에서 글이 사라진다.** `tests/team-board-private.test.js` 가 막는다.
  · 배포 순서는 **코드 먼저, SQL 나중**이다. 반대로 하면 옛 코드가 목록을 못 받는다.
    `loadPostBody` 에 폴백이 있어 SQL 이 늦어도 안전하다.
- `post.html` 사이드바는 글이 속한 게시판과 같아진다 (`initPostSidebar`).
  팀 글이면 최신 콘텐츠·창립 팬 100인 카드가 붙어 `team.html` 과 같고, 전체 글이면
  기존 2장 그대로여서 `community.html` 과 같다.
- 캐시 버전은 전 페이지와 런타임 자산 모두 `?v=20260812f`다. SQL 변경은 없다.

## ★ 다음 작업자가 반드시 알아야 할 함정

- **뷰에 anon 기본 권한이 자동으로 붙습니다.** 이 프로젝트 public 스키마에는
  `alter default privileges ... grant all on tables` 가 걸려 있어, `create view` 하면
  anon에게 SELECT/INSERT/UPDATE/**DELETE**가 자동 부여됩니다. `v_match_winner`는
  단일 테이블 뷰라 갱신 가능 뷰가 되고, `security_invoker=off` 라 소유자 권한으로
  RLS를 통과합니다 — 즉 `DELETE /rest/v1/v_match_winner` 한 방에 **matches가 통째로
  지워집니다**(재현해서 확인함). **새 뷰를 만들면 반드시 `revoke all ... from public,
  anon, authenticated` 를 먼저 하고 `grant select`만 주세요.**
- **Security Advisor의 `security_definer_view` 경고는 의도된 것입니다.**
  `security_invoker`를 켜면 anon이 기반 테이블 권한이 없어 모든 집계가 0으로 죽습니다.
  같은 이유로 이 테이블들에 `force row level security`를 켜면 안 됩니다.
- **승자 판정은 SQL(`v_match_winner`)과 JS(`matchWinner()`)가 같은 규칙이어야 합니다.**
  끝난 경기 + 양쪽 점수 있음 + 동점 아님. 한쪽만 고치면 적중률이 어긋납니다.
- **예측 마감도 두 곳이 같아야 합니다** — `vote_match`(SQL)와 `predictOpen()`(JS).
  둘 다 "경기 시작 5분 전"입니다. 화면이 그렇게 안내하고 있어서 서버가 그대로 지킵니다.
- **익명 시절 기록을 계정으로 옮기는 기능은 일부러 안 만들었습니다.** 익명 id가
  비밀이 아니라서(예전에 공개 조회였음) "id를 아는 사람이 주인"으로 인정하면

## 왜 바꿨나

## 재발 방지 (같은 날 이어서 작업 — 코드)

같은 사고가 또 나지 않게 두 가지를 넣었다.

**① 수집할 때 연결 표를 검사한다** — `api/_lp.js` 의 `checkAliases(map, players)` 신규.

- **겹침**: 서로 다른 두 이름이 한 선수 id 를 가리킴 → 한쪽 기록이 통째로 사라진다.
  단, `"Frog"` / `"Frog (Lee Min-hoi)"` 처럼 **같은 사람의 표기 차이는 정상**이라 뺀다
  (정규화한 닉네임이 하나면 넘어간다).
- **의심**: 이름과 똑같은 닉네임의 선수가 우리 DB 에 딱 한 명 있는데 다른 사람에게 이어져 있음.
- `api/leaguepedia.js` 가 결과 요약에 `연결겹침` · `연결의심` 으로 실어 보내고,
  관리자 화면 수집 결과에 **빨간 경고 한 줄**로 뜬다.
- **막지는 않는다.** 진짜 개명(두 이름 → 한 사람)이 정상인 경우가 있어서, 막으면 수집 자체가 멈춘다.
  대신 눈에 띄게 알리고 바로 고칠 수 있게 했다(아래 ②).

**② 이미 이어 둔 이름도 화면에서 고친다** — `admin.html` 의 `renderAliasLinks()` 신규
(수집 탭, "이어 둔 이름 고치기").

- 기존 표는 "못 알아본 이름"만 보여 줬다. **한번 잘못 이어진 이름은 이미 이어져 있어서 거기 안 뜬다** —
  그래서 화면에서는 고칠 방법이 아예 없었고, 이번처럼 SQL 을 써야 했다.
- 기본은 **문제 있는 것만** 보여 주고(`전체 보기` 로 전부), 각 줄에 지금 이어진 선수가 선택된 채로 뜬다.
  다른 선수로 바꾸거나 `— 연결 끊기 —` 로 끊을 수 있다(**끊기가 처음 생겼다** — 예전 저장 코드는
  빈 값을 무시해서 지울 수가 없었다).
- 검사 규칙 3가지: 겹침 · **없는 선수 id** · 닉네임 불일치. 없는 선수 id 는 그 값이 선택된 채로
  보여 줘서 저장할 때 조용히 끊기지 않게 했다.
- `assets/store.js` 에 `reloadSetting(key)` 추가. 수집기가 `lp_aliases` 에 자동 연결을 덧붙이므로
  수집 직후에는 화면이 든 값이 옛것이다. **저장 직전에 서버 값을 다시 받는다** —
  예전에는 수집 직후 "연결 저장"을 누르면 방금 서버가 이어 둔 이름이 날아갈 수 있었다(잠재 버그).
